# 质量打磨路线：保持本地单用户，不做账号与支付

产品现状是单用户本地刷题桌面工具。面对「像成熟的商业产品」的目标，我们在三条路线（纯质量打磨 / 桌面软件收费加授权 / 转型多用户 SaaS）中选择了**质量打磨**：不引入用户体系、支付、License 或云端服务，把资源全部投入完成度与体验——补齐半成品功能、稳定性、备份、更新与引导。

## Considered Options

- **桌面软件收费**（License + 试用期）：保留。若未来商业化，在此架构上加授权校验即可，不冲突。
- **转型 SaaS**（多用户 + 云端题库 + 订阅）：否决。单用户 SQLite 数据层、手写级联、本地文件导入均为单用户设计，改造成本接近重写，且与当前产品价值（本地、隐私、离线）相悖。

## Consequences

- 所有「多用户/登录/JWT」相关的 roadmap 条目（API.md 中遗留）应移除而非待开发。
- API 中的 `source` 等预留字段、无鉴权接口是**有意为之**，不是遗漏，后人不要「补全」。
